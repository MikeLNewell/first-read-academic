Responsible AI by design

What First Read does, and where it deliberately stops.

The system is designed as decision-support for educators. It prepares a structured first read against a verified assessment profile, then requires meaningful lecturer review before feedback can be exported.

Trust Layer v1.0 · September 2026
01

Human approved

AI output remains a draft. Copying, exporting and printing are locked until the lecturer explicitly confirms that they have reviewed the feedback.

02

Assessment bound

Live reviews can only use an assessment profile that a lecturer has checked and explicitly verified. Editing that profile revokes verification.

03

No automated grades

First Read is instructed not to produce marks, classifications, pass/fail outcomes or other consequential academic decisions.

04

No misconduct detection

First Read does not decide whether work was produced using AI and does not make academic misconduct allegations.

What the AI does

Prepares evidence-led observations

  • Compares the submitted work with the verified brief, learning outcomes and rubric.
  • Identifies candidate strengths and development priorities.
  • Links criterion comments to evidence or an identifiable location in the submission where possible.
  • Flags uncertain or externally verifiable issues for lecturer checking rather than presenting them as settled facts.
  • Produces an editable student-facing draft.

What the AI does not do

Does not replace academic judgement

  • Does not assign a mark, grade or classification.
  • Does not determine whether academic misconduct occurred.
  • Does not introduce hidden assessment requirements.
  • Does not treat grammar, fluency or presentation as a proxy for academic quality unless the rubric explicitly requires it.
  • Does not automatically send feedback to students.

Data flow

Minimal persistence, clear boundaries

1Lecturer chooses file

The original file stays local until the review is started.

2Transient processing

The file is sent through the authenticated Netlify function. The original filename is replaced before model processing.

3AI service processing

The configured OpenAI API processes the submission. Provider-side retention depends on the account and endpoint controls in force.

4No submission database

First Read does not write student submission files to the Supabase assessment library.

Known limitations

Useful output can still be wrong.

Large language models can overlook evidence, misread disciplinary nuance, over-value fluent presentation, infer unsupported conclusions and generate plausible but incorrect observations. Lecturer verification is therefore a core part of the workflow, not a disclaimer.

Fairness

Separate academic quality from surface style.

The review prompt explicitly directs the model not to penalise language, grammar, writing style or presentation unless those features are part of the published assessment criteria. Users should still monitor outputs for systematic bias.

Institutional governance still matters

First Read is designed to support responsible implementation, not to determine an institution's lawful basis or assessment policy. Before live use, institutions should consider data protection requirements, any DPIA, approved AI providers, student transparency, contractual/subprocessor arrangements and local assessment regulations.
